# 三大主案例证据系统设计

日期：2026-07-30

## 1. 目标

重做飞书 AI 业务数据平台、Service Agent 和光砚 Lumen 三个主案例的详情页，使招聘方能快速理解项目，同时让产品负责人和技术面试官继续核验判断、实现与证据。

每个案例页必须回答六个问题：

1. 这是一个什么项目，我承担了什么职责？
2. 为什么要做，当时做了哪些业务判断？
3. 产品以什么形态解决问题，关键流程是什么？
4. 技术上如何实现，关键取舍是什么？
5. 产品经过了哪些重要迭代，结果如何验证？
6. 有哪些公开安全、可复核的项目证据？

最终页面采用用户确认的 A 方案：编辑式长页、紧凑浅色导航、产品与技术并重、证据集中展示。页面延续当前官网的连续纸张视觉，不引入独立的工程控制台风格。

## 2. 成功标准

- 招聘方进入案例页后，可以立即看到板块总数、当前板块、项目状态、职责和最新验证日期。
- 产品内容包含业务背景、优先级判断、产品形态、关键流程、约束和取舍。
- 技术内容说明系统结构、关键机制及其业务作用，不堆叠技术名词。
- 迭代内容说明问题、决策、改动和验证结果，不把 Git 历史直接搬到页面。
- 证据区支持真实截图、视频、体验入口、架构图、验证报告和能力边界。
- 所有公开数字、状态和部署表述来自权威包，并带有适用范围与证据引用。
- 三个案例共用同一阅读结构，但事实、证据、状态和边界完全独立。
- 文案自然、具体、克制，减少口号、对仗、模板化总结和“不是……而是……”句式。

## 3. 范围与非目标

### 3.1 本次范围

- 三个主案例详情页：`data-platform`、`service-agent`、`lumen-ink`。
- 三个案例在首页卡片、项目库和 AI 导览中的状态摘要同步。
- 六板块案例模板、锚点导航、当前板块指示和移动端导航。
- 最新公开事实、结构化指标、证据目录和能力边界。
- 三个案例的截图盘点、脱敏、替换和缺口标记。
- 视频与体验入口的数据结构、展示状态和降级行为。
- 结构化一致性检查、响应式验证和无障碍验证。

### 3.2 非目标

- 不重做首页整体结构和视觉系统。
- 不重写其余扩展项目的详情页；它们继续使用现有模板。
- 不修改 Service Agent、Lumen、飞书或 Collator 的产品代码与线上配置。
- 不执行生产写入、飞书 Pilot、通知、服务环境变量修改或真实客户操作。
- 不把计划中的视频、未重新采集的截图或不可用体验入口呈现为现有证据。
- 不生成新的业务效果百分比、准确率、SLA 或用户规模。
- 不在本阶段部署官网；发布需要单独的预览验收与生产授权。

## 4. 权威来源与冲突处理

### 4.1 公开内容读取顺序

公开状态和数字只按以下顺序读取：

1. `01-PUBLIC-SOURCE-OF-TRUTH.yaml`：当前状态、部署、案例边界和结构化指标。
2. `02-CLAIMS-EVIDENCE-MATRIX.md`：允许公开的具体表述、数字与 evidenceRef 绑定。
3. `12` 至 `16` 的专项报告：用于形成证据对象和解释验证过程。
4. `06-PROHIBITED-CLAIMS.md`：只应用与第 1、2 项不冲突的禁止项和安全边界。
5. `05-WEBSITE-CONTENT-SNAPSHOT.md`、`07-FINAL-HANDOFF.md` 等历史快照：仅用于追踪旧状态，不作为当前页面文案。

当同一目录内文件存在旧状态时，页面不得自行折中。状态文案以 `01` 和 `02` 为准，专项报告只支撑对应证据。实现门禁需要列出冲突并失败，避免旧快照覆盖当前状态。

## 5. 页面信息架构

### 5.1 页面首部

首部包含：

- 案例序号、分类与项目名称。
- 一句具体的项目说明，避免广告式标题。
- 本人职责、项目周期、当前状态、验证日期和主要入口。
- 3 至 4 个最强公开指标；每项同时显示范围说明，不只显示大数字。

首部不放完整技术栈、长段背景或多个同级 CTA。体验入口是主要动作，证据区锚点和下一案例为次要动作。

### 5.2 紧凑导航

导航固定为六项：

1. 项目概览
2. 业务判断
3. 产品方案
4. 技术实现
5. 迭代链路
6. 项目证据

桌面端使用内容区内的浅色浮条，而不是满宽深色通栏：

- 高度约 `44px`，外层与正文左右边界一致。
- 左侧显示 `当前序号 / 总数` 和当前板块名称。
- 当前项使用淡雾紫底 `#E7DDE9`、深梅紫字 `#4F4054` 和鼠尾草绿状态点 `#718C7B`。
- 其他项使用浅纸面、细边框和低对比文字。
- 使用 `IntersectionObserver` 更新当前板块，点击后平滑滚动并补偿固定 Header。
- 当前链接使用 `aria-current="location"`；键盘与辅助技术可读取板块状态。

移动端保持单行横向安全滚动，不能换行挤压正文，也不能造成页面级横向溢出。

### 5.3 板块一：项目概览

用最短篇幅说明：

- 项目服务的业务与用户。
- 本人职责和关键协作对象。
- 产品当前形态与可用范围。
- 最新验证结果和状态。

四个摘要指标必须从结构化 claim 读取。状态与指标不是同一字段，避免用一个数字代替整体判断。

### 5.4 板块二：业务判断

包含三个层次：

- 业务问题：当时发生了什么，为什么值得投入。
- 首期优先级：选择解决哪些问题，哪些暂缓。
- 产品约束：安全、权限、成本、时延、现场使用或运营条件。

该板块以真实工作场景和决策为主，不提前展开完整技术架构。

### 5.5 板块三：产品方案

包含：

- 产品形态：Web、移动端、飞书 Base、Agent 对话或图像工作台。
- 主要用户和任务。
- 从输入到结果的核心流程。
- 重要状态、人工节点、失败路径和降级策略。
- 关键产品决策及其原因。

流程图最多保留 5 至 7 个用户可理解的步骤。技术节点放到下一板块，避免产品流程与代码架构混在一张图里。

### 5.6 板块四：技术实现

只展示对产品结果有直接影响的技术内容：

- 系统边界与主要组件。
- 数据如何进入、处理、存储和输出。
- 关键门禁、权限、幂等、恢复或安全策略。
- 一到三个关键技术取舍，并解释其产品影响。
- 真实技术证据入口，如架构图、测试、部署和运行时验证。

技术栈用辅助标签呈现，不作为主体叙事。

### 5.7 板块五：迭代链路

每个案例选择 3 至 4 次有产品意义的变化。每次迭代使用统一结构：

- 发现的问题。
- 当时的判断。
- 方案变化。
- 验证方式与结果。

Service Agent 使用 Deploy 028、031/032、039 形成一条清楚链路。飞书案例使用历史 V1 基线、V2 目标模型、测试 E2E、生产只读 Schema 验证。Lumen 使用受控演示、生产健康与认证边界、Seedream 真实编辑验证。

迭代链路不展示全部 commit，也不把失败隐藏。失败版本必须说明为何不能发布，以及后续如何关闭问题。

### 5.8 板块六：项目证据

证据区采用混合证据，不依赖单一截图：

- 真实界面截图或脱敏响应截图。
- 60 至 90 秒产品视频，支持封面、时长与章节。
- 受控体验入口及其可用状态、失败说明和备用入口。
- 架构图或流程图。
- 测试、部署、Schema diff、HTTP 验证等摘要卡。
- 已验证能力与尚未证明内容。

最强证据默认显示 3 至 5 项，其余证据可通过详情或轻量展开查看。每项证据必须显示：

- `evidenceId` 或 evidenceRef。
- 证据类型。
- 状态：`available`、`planned`、`unavailable`。
- 验证日期。
- 证明范围。
- 公开安全状态。
- 资源地址或体验入口。
- 必要的边界说明。

`planned` 和 `unavailable` 不渲染成可播放视频、可操作 Demo 或已完成验证。

## 6. 三个案例的内容重点

### 6.1 飞书 AI 业务数据平台

产品重点：

- 摄影业务数据分散、协作依赖人工同步的问题。
- 统一数据模型、现场移动作业、三态治理 Gate、精确清理与审计。
- Collator 是非结构化摄入子系统，不单独升级为第四个主案例。

技术重点：

- 飞书多维表、Node.js、移动端与 CloudBase 的边界。
- 摄入、候选、人工确认、治理、测试写入、幂等和精确清理。
- 生产只读 Schema 验证 10/10 表、216 字段；字段级 diff 和生产写入仍关闭。

建议证据：

- 脱敏后的生产 V2 表级 Schema 对比图。
- 测试 Base E2E 五步链路图与 49/49 Pilot gate 摘要。
- Portal 受控体验入口与清楚的测试环境说明。
- 60 至 90 秒流程视频；未采集前保持 `planned`。

### 6.2 Service Agent

产品重点：

- 常规咨询、高风险问题和无知识问题的处理差异。
- B1/B2/B3 场景语言、人工接管与知识缺口回收。
- 当前后端上线、前端静态降级的产品状态。

技术重点：

- LangGraph 8 节点 11 边。
- N03.5 Query Resolver、多查询融合、检索证据与上下文支持双层门禁。
- R0-R3 风险分级和确定性硬风险 fail-closed。
- Deploy 039 的 Phase G 已验证，以及可用性、时延和知识覆盖边界。
- `16/16 smoke` 与 `Turn 2 3/3` 目前只存在于验证报告，尚未进入声明—证据矩阵；在获得 claimId 与 evidenceRef 前不得展示为公开数字。

建议证据：

- Deploy 039 的脱敏多轮真实响应与 source_modules。
- B1/B2/B3 受控体验入口。
- 90 秒产品演示视频；未采集前保持 `planned`。
- 工作流图、Phase G 摘要和 Deploy 028→031/032→039 迭代卡。
- 移除现有 Trae 调试失败、LoRA Factory、旧 LangSmith 和旧飞书工作流等误导素材。

### 6.3 光砚 Lumen

产品重点：

- 专业修图需求如何被组织为工作台、工具和结构化提示词。
- 模型选择、参数控制、结果对比和版本回看。
- Live Demo 的使用方式与 BYO Key / 认证边界。

技术重点：

- 统一 Provider 抽象、认证与密钥处理。
- Production root、`/api/health=200`、未授权请求 `401`。
- Seedream 4.5 文生图与图生图 2/2 真实编辑验证。
- 液化、修复、消除等模式尚未验证。

建议证据：

- 文生图与图生图输入—输出对照。
- Provider、Model、HTTP 结果和安全检查摘要。
- Lumen Live Demo 入口。
- 60 至 90 秒操作视频；未采集前保持 `planned`。
- 现有产品界面图可保留，但需要逐张检查其版本、功能与验证状态。

## 7. 内容与组件设计

### 7.1 数据边界

保留 `content/projects.ts` 作为全部项目的基础目录和卡片数据。新增主案例详情层，只覆盖三个 featured slug：

```ts
type FlagshipCaseStudy = {
  slug: "data-platform" | "service-agent" | "lumen-ink";
  verifiedAt: string;
  overview: CaseOverview;
  business: BusinessSection;
  product: ProductSection;
  technology: TechnologySection;
  iterations: CaseIteration[];
  evidence: PortfolioEvidence[];
  boundary: CapabilityBoundary;
};
```

使用 `content/flagship-cases/` 目录：`types.ts` 定义共享类型，`data-platform.ts`、`service-agent.ts`、`lumen-ink.ts` 分别保存三个案例事实，`index.ts` 只负责导出和按 slug 查询。这样可以避免继续扩大已经承载全部项目的 `projects.ts`。三个案例共享类型，不共享事实对象。

### 7.2 证据目录

扩展现有 `content/portfolio-evidence.ts`，而不是创建第二套证据系统。证据对象至少增加：

```ts
type PortfolioEvidence = {
  id: string;
  projectSlug: string;
  kind: "image" | "video" | "interactive" | "architecture" | "test" | "document";
  title: string;
  summary: string;
  state: "available" | "planned" | "unavailable";
  publicSafe: boolean;
  evidenceRefs: string[];
  verifiedAt?: string;
  scope: string;
  boundary?: string;
  assetUrl?: string;
  thumbnailUrl?: string;
  href?: string;
  fallbackHref?: string;
  durationSeconds?: number;
  chapters?: Array<{ label: string; seconds: number }>;
};
```

生产构建不得渲染 `publicSafe=false` 的资源。`planned` 只显示“待补素材”，且不生成可点击的播放或体验控件。

### 7.3 页面与组件

建议组件边界：

- `FlagshipCasePage`：组合六个板块，接收完整 `FlagshipCaseStudy`。
- `CaseSectionNav`：固定六项、滚动同步、键盘与移动端行为。
- `CaseOverview`：职责、状态和结构化指标。
- `BusinessContext`：问题、优先级和产品约束。
- `ProductDesign`：产品形态、流程、状态与决策。
- `TechnicalImplementation`：架构、关键机制和技术取舍。
- `IterationPath`：三到四次产品迭代。
- `EvidenceGallery`：截图、视频、体验、报告和边界。

`app/projects/[slug]/page.tsx` 只负责读取 slug 并选择模板：有主案例详情数据时渲染新模板，其余项目继续渲染现有页面。这样可以在不重做全部项目的情况下完成三个案例升级。

## 9. 文案规则

- 标题优先使用事实性名词和动作，如“业务判断”“产品形态与关键流程”“技术实现与关键取舍”。
- 段落先写场景和决策，再写总结；避免每段都从抽象结论开始。
- 同一页面不重复使用“三个重点”“两层能力”“一条闭环”等整齐句式。
- 避免“不是……而是……”“不止……更……”等高频模板句。
- 不使用“赋能、重塑、全链路、业界领先、端到端智能化”等无证据词语。
- 技术名词出现时必须说明它解决的产品问题。
- 失败和限制使用直接陈述，不使用委婉营销语言。
- 允许第一人称说明职责与判断，但不把团队成果全部写成个人完成。

## 10. 素材与安全

### 10.1 文件组织

建议按案例组织：

```text
public/evidence/
  data-platform/
  service-agent/
  lumen-ink/
```

每个目录可包含 `images/`、`video/`、`posters/` 和生成后的架构图。文件名使用语义化英文和验证日期，不使用随机编号。

### 10.2 脱敏要求

发布前必须移除或遮盖：

- Base token、table id、chat_id、open_id、客户姓名、手机号和真实记录。
- 本地绝对路径、个人邮箱登录态、浏览器账户标识和内部环境 ID。
- API key、JWT、Secret、请求头和可重放凭据。
- 未经授权的客户图片、对话、业务金额和生产数据。

飞书现有看板截图和 Service Agent 现有调试截图不能直接沿用。每张素材都要经过逐项检查，并记录 `publicSafe` 结论。

### 10.3 视频行为

- 不自动播放，不默认加载大体积视频。
- 使用本地封面、明确时长和章节导航。
- 提供字幕或文字摘要。
- 视频失败时显示封面、摘要和备用入口，不出现空白播放器。
- 未采集完成时保持 `planned`，页面明确显示“待补素材”。

### 10.4 体验入口

- 入口必须显示体验类型：Public、Controlled、Local-only 或 Unavailable。
- 显示最近验证日期和已知边界。
- 主入口失败时提供页面内证据锚点或联系入口。
- 不在页面后台主动调用会产生写入的服务。

## 11. 响应式与无障碍

- 桌面端导航与正文内容区对齐，不使用满宽通栏。
- 平板端保留六项导航；必要时缩短英文辅助文字，不删除中文板块名。
- 移动端导航单行横向滚动，并通过渐隐边缘提示仍有内容。
- 锚点目标使用 `scroll-margin-top`，避免被 Header 和案例导航遮挡。
- 视频、截图和架构图提供准确的 alt 或文字摘要。
- 所有体验、播放、展开与导航控件支持键盘操作和可见 focus。
- 状态不能只用颜色表达；必须同时显示文字。
- 支持 `prefers-reduced-motion`，关闭平滑滚动和位移动效。

## 12. 验证设计

### 12.1 结构化一致性

扩展现有 `check:portfolio` / consistency gate：

- 三个主案例必须各有六个板块。
- 所有公开数字必须存在于 `public-claims.json` 并绑定 evidenceRef。
- 验证报告中的数字若尚未进入 `02-CLAIMS-EVIDENCE-MATRIX.md`，只能用于内部核验，不得直接进入页面、首页卡片或 AI 导览语料。
- 页面状态与权威包当前状态一致。
- evidenceRef 唯一、存在且与案例匹配。
- `available` 资源文件或 URL 必须存在；`planned` 不得渲染为可操作入口。
- `publicSafe=false` 不得进入生产渲染。
- withdrawn / prohibited 文案扫描覆盖三个案例、首页卡片和 AI 导览语料。

### 12.2 组件与交互

- 六项导航顺序固定，滚动时 `aria-current` 只出现在当前项。
- 点击导航后标题不被固定 Header 遮挡。
- 移动端导航可滚动且页面无横向溢出。
- 视频不可用时显示正确降级状态。
- 体验链接包含类型、验证日期和边界说明。
- 主案例使用新模板，扩展项目仍使用旧模板。

### 12.3 视觉与浏览器验证

至少验证 `390 / 768 / 1440` 三个宽度：

- 导航高度、当前状态和官网色板一致。
- 产品与技术内容比例清楚，没有大面积空白或深色通栏。
- 证据截图不变形，视频封面和入口状态明确。
- 长标题、英文术语和 evidenceRef 不溢出。
- 三个案例之间保持一致结构，同时能明显区分内容与状态。

### 12.4 工程门禁

- `npm run test:v5`
- `npm run test:guide`
- 新增案例模板与证据目录测试
- `npm run lint`
- `npm run check:portfolio`
- `npm run build -- --webpack`
- 预览部署后的首页、三个案例页、robots、sitemap、简历和外链烟测

## 13. 实施边界与发布

- 实施从当前 `origin/main` 创建隔离分支和工作树。
- 保留用户现有脏工作树，不在其中混入修改。
- 内容更新、模板组件、素材和验证门禁拆分为可审查提交。
- 不提交真实凭据、原始敏感截图或生产标识。
- 先完成本地构建与浏览器验证，再生成 Preview。
- Preview 经用户确认后，才允许合并、推送生产分支或部署正式站点。
- 官网发布不自动触发 Service Agent、Lumen 或飞书的外部写入与部署。
