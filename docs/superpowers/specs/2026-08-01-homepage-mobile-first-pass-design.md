# 首页移动端第一轮优化设计

**Project ID:** MONOREPO-PORTFOLIO
**Task ID:** HOMEPAGE-MOBILE-FIRST-PASS-01
**Status:** APPROVED_FOR_IMPLEMENTATION
**Scope:** 首页移动端 Hero、AI 导览入口、项目库去重、数据飞轮与可读性

## 目标

在不改变桌面端现有叙事和不触碰详情页未提交改动的前提下，降低 360–430px 手机首页的首屏认知负担、纵向滚动成本和阅读门槛。

## 设计决策

### Hero

Hero 保留现有桌面结构。手机端使用独立的摘要与证据变体：

- 保留身份标签、核心价值主张和两行短摘要。
- 保留查看主案例与 AI 快速判断两个 CTA，均不低于 44px 高。
- 新增只在手机端呈现的三个关键证据数字。
- 手机端不呈现 Hero 内的简历、GitHub、Email、复杂 AI 提示卡和能力索引。
- 桌面端继续保留既有简历入口、AI 提示卡和三项能力索引。

### AI 导览

PortfolioGuide 保持既有请求、流式回答、证据来源和错误处理逻辑，仅改变入口形态：

- 桌面端继续显示完整导览窗口。
- 手机端只显示一张可聚焦的入口卡。
- 入口打开同一个完整导览窗口的全屏 Sheet，不复制聊天 DOM 或表单状态。
- 手机角色选择使用三等分横向分段控件，长说明仅显示当前角色。
- Sheet 关闭后恢复触发按钮焦点，并锁定页面滚动。

### 项目库

ProjectLibrary 使用 matchMedia 的响应式快照决定实际渲染数据，而不是通过 CSS 隐藏旗舰卡：

- 手机默认只渲染 6 个非旗舰项目。
- LoRA 项目使用稳定的项目编号 04，并排在扩展项目第一位。
- “查看全部九个项目”会切换为全部项目，手机仍使用紧凑语义列表。
- 桌面端渲染完整九项目结构。
- 手机紧凑卡不渲染大型图片媒体，因此不会留下不可见图片或焦点节点。

### 数据飞轮

桌面端继续使用环形飞轮。手机端渲染六步纵向有序列表和末端回环提示。两种变体分别通过 CSS 显示，手机端不再使用缩放、负 margin 或 620px 固定占位。

### 可读性与边界

- 手机正文不低于 14px，辅助说明和标签不低于 11px。
- 手机按钮、角色 Tab、列表行和 Sheet 关闭控件不低于 44px 高。
- 页面使用 overflow-x: clip 或真实的局部横向滚动，不使用 overflow-x: hidden 掩盖布局问题。
- 详情页文件、详情页测试、详情页 spec/plan 和既有 artifacts 不修改、不整理、不覆盖。

## 测试与验证

新增首页移动端契约测试，覆盖 Hero 变体、Sheet 单实例、项目库条件渲染、LoRA 编号、飞轮语义列表、字号底线和 overflow-x 边界。完成后运行 TypeScript、现有首页/导览/项目契约测试、生产 build，并在 360、375、390、430px 检查 document.documentElement.scrollWidth === document.documentElement.clientWidth。
