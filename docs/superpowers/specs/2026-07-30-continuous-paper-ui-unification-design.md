# 官网 A 方案：连续纸张编辑流 UI 统一设计

日期：2026-07-30  
状态：已由用户确认视觉方向，等待规格复核  
实施基线：`origin/main` at `da525f8`

## 1. 目标

在不调整首页信息结构和公开内容的前提下，把当前只覆盖首屏与旗舰案例的编辑感视觉语言延伸到整页，解决以下问题：

- Hero 与旗舰案例之间留白叠加，产生明显断层。
- 产品架构、产品方法、AI 导览连续切换梅紫、纯黑和绿黑满宽色块，颜色过多且割裂。
- 后半页重新使用满宽直角色块，与首屏的柔和纸张、轻叠层和异形圆角不一致。
- 大标题、正文、说明文字的字号跨度过大，小字可读性不足，重点层级不稳定。

最终效果应保留当前编辑感和专业度，同时更灵动、连续、克制；用户滚动时应感觉是在阅读同一本作品集，而不是进入多个独立模板。

## 2. 已确认方向

采用 A「连续纸张编辑流」：

- 米白色作为整页连续底纸，不再让每个模块自行定义大面积背景色。
- 深色只用于少数内嵌章节卡、按钮和页脚，不再连续出现多个满宽深色章节。
- 鼠尾草绿作为 AI 导览和状态提示的辅助色；淡雾紫只用于轻量层次和过渡。
- 延续首屏的细边框、纸张颗粒感、轻叠层、异形圆角和柔和投影。
- 通过卡片错位、局部重叠和不完全对称增加灵动感，但不改变内容顺序。

高保真确认稿以设计会话中的 `visual-unity-real-content-v3.html` A 状态为视觉基准。

## 3. 范围与非目标

### 3.1 本次范围

- 全局颜色、字体层级、间距、圆角、边框和投影令牌。
- Header、Hero、三个旗舰案例、产品架构、产品方法、AI 导览、完整项目库、经历、联系与页脚的视觉统一。
- 桌面、平板和移动端响应式排版。
- 现有交互的 hover、focus、sticky header、锚点滚动和 AI 导览状态视觉。
- 视觉回归与首页结构契约补强。

### 3.2 非目标

- 不改变首页模块顺序和导航信息架构。
- 不改写公开文案、项目指标、项目状态、证据边界或简历链接。
- 不改变三个主案例的同优先级关系。
- 不删除、缩减或降级 AI 导览；它仍是 Hero 入口与独立完整章节。
- 不修改 AI 导览 API、检索、模型、流式回答、限流和回退逻辑。
- 不重构项目详情页内容结构；只允许共享令牌产生的必要视觉同步。
- 不增加新的图片、视频、外部字体或第三方 UI 依赖。

## 4. 视觉系统

### 4.1 颜色

以现有暖米白、深梅紫和鼠尾草绿为基础，收敛成四类表面：

| 角色 | 建议值 | 用途 |
| --- | --- | --- |
| 连续底纸 | `#F3EEE4` | 页面主背景、区块之间的连续空间 |
| 浅纸面 | `#FBF8F1` | Header、卡片、AI 窗口、信息面板 |
| 主文字 | `#1C1820` | 标题、正文重点、深色按钮 |
| 深梅紫 | `#4F4054` | 产品架构内嵌章节、主要按钮、页脚 |
| 鼠尾草绿 | `#718C7B` | AI 导览、在线状态、标题划线、轻投影 |
| 淡鼠尾草 | `#DFE7DE` | AI 导览章节底面和状态层 |
| 淡雾紫 | `#E7DDE9` | 轻量过渡、次级表面，不作为大面积深色章节 |

规则：

- 单个视口最多出现一个大面积深梅紫区域。
- 禁止新增纯黑或绿黑满宽章节背景。
- 所有正文在其表面上的对比度至少满足 WCAG AA。
- 项目状态条可保留半透明深色，但不能与正文主层级竞争。

### 4.2 字体层级

- 展示标题继续使用中文宋体风格的现有 serif 字体栈；正文沿用现有 sans 字体栈。
- Hero 标题在桌面端保持强表达，但缩小极端字号差距；正文基准不低于 `16px`。
- 卡片正文不低于 `14px`，辅助说明不低于 `12px`，仅英文 eyebrow 和数据标签可使用 `11px`。
- 正文行高保持 `1.65–1.85`，长段落最大行宽控制在约 38–46 个中文字符。
- 所有标题、正文和辅助说明使用统一的流体字号区间，避免断点处突然跳变。

### 4.3 形状与层次

- 主章节容器使用 `24–48px` 的不对称圆角；内部卡片使用 `14–30px` 圆角。
- 阴影统一为低对比、宽模糊阴影，禁止硬黑投影。
- 边框统一使用主文字的 12%–18% 透明度。
- 允许旗舰案例第二张卡片轻微下移、章节卡轻微错位投影和局部重叠，以增加灵动感。
- 所有装饰必须 `pointer-events: none`，不得覆盖真实交互区域。

### 4.4 动效

- 只保留短时、低幅度动效：卡片 hover 上移、按钮色面变化、AI 在线状态呼吸。
- 动效时长以 `180–320ms` 为主，使用 ease-out。
- 支持 `prefers-reduced-motion: reduce`，关闭位移和循环动画。
- 不新增大范围滚动视差、鼠标跟随或影响阅读的入场动画。

## 5. 各模块设计

### 5.1 Header

- 保留现有导航和固定位置。
- 使用半透明浅纸面、细边框和轻模糊；圆角与 Hero 视觉一致。
- 导航文字保持可读，不用过小字号。
- 简历按钮继续使用深梅紫作为唯一强 CTA。

### 5.2 Hero

- 保留现有双栏结构、真实文案、三项核心能力、公开证据摘要和三个 CTA。
- `AI 导览` 作为明确的第二 CTA，名称保持简洁，不使用“让 AI 90 秒介绍我”。
- 保留 Hero 内的 AI 导览邀请卡和三个角色入口。
- 用鼠尾草绿手绘式划线或纸张洗色强调“可上线、可评估”，避免渐变大字。
- 缩短 Hero 底部空白，让 AI 导览邀请卡、外链和旗舰案例自然衔接。

### 5.3 三个旗舰案例

- 保持三张卡片同尺寸、同信息层级和同优先级。
- 使用真实项目界面图片与现有状态文本。
- 允许中间卡片轻微下移形成编辑排版节奏，但移动端恢复单列对齐。
- Hero 与该章节之间使用同色底纸、细线和局部纸张凸起过渡，不再叠加两段大留白。

### 5.4 产品架构

- 作为全页最主要的深梅紫内嵌章节卡，而不是满宽背景带。
- 保留五层系统结构、全部项目节点和旗舰/案例标识。
- 每层使用半透明线框容器；层级信息和项目标签均保持可读。
- 章节卡通过浅鼠尾草错位投影与连续底纸连接。

### 5.5 产品方法

- 回到浅纸面，紧随产品架构形成“深色架构 → 浅色方法”的单次明暗节奏。
- 保留四项原则和数据飞轮。
- 原则采用两列编辑网格；飞轮采用深梅紫中心与浅色步骤卡，不再使用纯黑大背景。
- 平板和移动端改为单列，先方法文字后飞轮。

### 5.6 AI 导览

- 保持完整独立模块及所有真实交互状态。
- 使用淡鼠尾草表面承接方法章节，导览窗口使用浅纸面。
- 保留三种角色、欢迎消息、推荐问题、输入框、发送/停止、等待、流式回答、来源和错误/回退状态。
- 在线、只读、可追问等状态使用鼠尾草绿，不引入新的亮色。
- 输入和按钮必须维持清晰 focus 样式、disabled 状态和触摸尺寸。

### 5.7 项目库、经历与联系

- 项目库回到连续米白底纸，筛选与卡片共享旗舰案例的边框、圆角和正文层级。
- 经历使用极浅雾紫纸面作为轻章节分隔，不使用满宽深色。
- 联系与页脚保留深梅紫，作为整页唯一结尾色块，与产品架构形成首尾呼应。
- 页脚圆角、边距和内容宽度与前文一致，避免突然贴边。

## 6. 响应式规则

### 6.1 桌面端（`>= 1200px`）

- 内容最大宽度沿用现有 `section-shell` 体系。
- Hero 双栏；旗舰案例三列；方法和 AI 导览双栏。
- 章节留白更紧凑，避免出现超过一个视口三分之一的无内容区域。

### 6.2 平板端（`768–1199px`）

- Hero 可在窄平板转为单列，核心能力紧随主文案。
- 旗舰案例优先三列压缩到两列或单列，不允许正文小于约定下限。
- 架构层与方法布局转为单列，AI 导览窗口保持完整宽度。

### 6.3 移动端（`< 768px`）

- 所有主模块单列，水平边距保持 `18–24px`。
- Header 使用现有菜单按钮，不改变导航内容。
- Hero 标题按语义断行，不允许溢出或单字悬挂。
- AI 导览角色标签、推荐问题和输入区域允许横向安全滚动或纵向堆叠，不遮挡发送按钮。
- 禁止横向页面溢出；触摸目标最小高度约 `44px`。

## 7. 实施边界

预计主要修改：

- `app/editorial-responsive.css`：把当前只覆盖 Hero 与旗舰案例的视觉规则扩展为整页系统。
- `app/globals.css` / `app/v5.css`：仅在需要消除旧满宽深色背景或重复规则时做最小调整。
- `components/home/*`、`components/SystemMap.tsx`、`components/PortfolioGuide.tsx`：原则上不改结构；只有现有 class 无法表达已确认视觉或无障碍状态时才做小范围 class/语义调整。
- `tests/v5-home-contract.test.mjs`：补充整页连续底纸、AI 导览保留、旧纯黑/绿黑色块移除和模块顺序不变的契约。

不得修改：

- `content/projects.ts` 和 `content/public-claims.json` 中的公开内容与证据。
- `app/api/portfolio-guide/route.ts` 以及 `lib/portfolio-guide*` 的行为。
- 项目图片、简历文件、案例状态和外部链接。

## 8. 验收标准

### 8.1 视觉与结构

- Hero、旗舰案例、产品架构、产品方法、AI 导览、项目库、经历和联系使用同一套颜色、形状和间距令牌。
- Hero 到旗舰案例没有叠加留白或被固定 Header 遮挡。
- 中段不再连续出现梅紫、纯黑、绿黑三个满宽色块。
- 产品架构为内嵌深色章节卡，产品方法为浅纸面，AI 导览为淡鼠尾草表面。
- 三个主案例保持同一优先级，AI 导览仍完整可见且可操作。

### 8.2 可读性与响应式

- 360、390、768、1024、1440 和 1920 像素宽度无横向溢出。
- 正文、标签和按钮达到本规格的最小字号与触摸尺寸。
- 键盘可以访问导航、案例链接、角色切换、问题建议、输入框和发送/停止按钮。
- `prefers-reduced-motion` 下不出现持续动画或明显位移。

### 8.3 工程验证

- `npm run test:v5`
- `npm run test:guide`
- `npm run lint`
- `npm run check:portfolio`
- `npm run build -- --webpack`
- 使用浏览器对桌面和移动端做整页截图，并重点检查 Hero→旗舰案例、产品架构→方法→AI 导览和项目库→经历→联系三处过渡。
